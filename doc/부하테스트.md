# 90만 사용자가 부른 서버 폭발, 어떻게 대처할 것인가?

## 실제 사례
- 2016년 콜드플레이 내한공연 티켓팅에 동접자 90만명으로 서버 다운
- 인터파크와 예스24 로 나눴지만 둘 다 서버 다운
- 한 서버당 45만명의 동접자를 처리해야 함

## 목표 및 전략
- 목표
  - 45만명의 사용자가 동시에 접속하는 대기열 시스템 구축
- Application/Redis Instance
  - 각 인스턴스당 2,500명의 사용자를 처리할 수 있는 시스템을 구축하여 200 개의 인스턴스로 대응
- Loadbalancer
  - 200개의 인스턴스를 로드밸런싱하여 45만명의 사용자를 처리

## 테스트 대상
- 인스턴스 패키지
  - Application 인스턴스 1개
  - Redis 인스턴스 1개
- 동접자: 2,500명

## 시나리오
- 초당 500명씩 접속
- 5초 후 대기열에 모든 사용자 2,500명 접속
- 접속 후 1초 마다 대기순서 조회
- 최대 RPS
  - 25,000 RPS = 25,000명 * 1(초당요청)

## 테스트 환경
- 인스턴스 구성
  - Test: K6
  - App: Tomcat
  - DB: Redis
- 목표지수
  - 실패율: 5% 미만
  - P95: 3000ms 미만
