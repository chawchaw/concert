# 결제와 충전 동시성 문제

## 기존 정책
- 결제: 여러 요청이 와도 한개만 성공
- 충전: 여러 요청이 와도 한개만 성공

## 변경된 정책
- 결제: 여러 요청이 와도 한개만 성공
- 충전: 여러 요청이 와도 모두 성공

## 변경한 이유
- 결제와 포인트 충전은 하나의 자원을 사용하므로 같은 락을 사용해야 합니다.
- 기존 정책
  - 각각의 동시성 문제시 결제는 하나만 성공, 포인트 충전도 한개만 성공입니다.
  - 결제는 대기시간을 1초로 설정했고(이때는 1초로 했을때의 성능을 모르고 있었습니다.)
  - 포인트 충전은 대기시간을 0초로 설정하여 성능을 향상했습니다.
  - 여기서 문제는 결제와 충전이 동시에 발생하면 결제는 항상 성공하지만 포인트충전은 불확실합니다.
  - 테스트 결과에서 결제 중 충전이 한번씩만 일어나면 결제는 성공하고 충전은 실패하지만 2번이상이 될 경우 충전이 되는 케이스가 생깁니다.
  - 따라서 이 정책은 동시성 제어가 어려운 케이스로 판단되어 충전도 모두 성공시키도록 변경하였습니다.
- 변경 정책
  - 결제는 1번만 실행되고 충전은 요청 수만큼 실행됩니다.
    - ex. 현재 잔액 1000원
      - 100원 결제 3번 요청
      - 50원 충전 3번 요청
      - 최종잔액 = 현재 잔액 - (결제금액 * 1) + (충전금액 * 3)
      - 최종잔액 = 1000 - (100 * 1) + (50 * 3) = 1000 - 100 + 150 = 1050원
